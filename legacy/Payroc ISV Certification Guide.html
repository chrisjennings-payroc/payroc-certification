Authentication — get a bearer token
0 / 2 ▼
Tokens expire in ~1 hour. Exchange your API key at the start of each session, or implement proactive refresh before expiry. The API key is your secret — never expose it to the browser.
POST https://identity.uat.payroc.com/authorize
# Request Header: x-api-key: YOUR_API_KEY # Response { "access_token": "eyJhbGc...", "expires_in": 3600, "token_type": "Bearer" }
  • UAT token exchange implemented Successfully calling POST /authorize on identity.uat.payroc.com and receiving access_token
    POST
  • Token attached to all requests Authorization: Bearer <access_token> header sent on every API call

Event Subscriptions — webhook registration
0 / 5 ▼
Register your webhook before submitting your first boarding request so no status change events are missed. Both event types must be subscribed — processing account and terminal order.
POST https://api.uat.payroc.com/v1/event-subscriptions
{ "enabled": true, "eventTypes": [ "processingAccount.status.changed", "terminalOrder.status.changed" ], "notifications": [ { "type": "webhook", "uri": "https://your-server.com/webhooks/payroc", "secret": "your-shared-secret-32-chars-min", "supportEmailAddress": "ops@yourcompany.com" } ] }
UAT access note: POST /v1/event-subscriptions requires an event-scoped API key. If you receive a 403, contact your Payroc integration contact to enable event access on your key.
  • Webhook endpoint publicly reachable Your endpoint returns HTTP 200 on receipt; Payroc retries up to 5× on failure

Error Handling — 4xx/5xx response handling
0 / 3 ▼
All Payroc errors follow RFC 7807 problem-details format, extended with an errors[] array. Each item in errors[] carries parameter (the failing JSON path), detail, and message. Read errors[].parameter to map failures back to your request body.
400 Validation error shape
{ "type": "https://docs.payroc.com/api/errors#bad-request", "title": "Bad request", "status": 400, "detail": "One or more validation errors occurred", "errors": [ { "parameter": "processingAccounts[0].owners[0].identifiers[0].value", "detail": "Invalid format", "message": "National ID must contain digits only" } ] }
  • 400 errors surfaced to operator with errors[].parameter Validation failures map back to specific fields; operator can correct and resubmit
    REQ
  • 409 idempotency conflict handled On 409, checks whether the original boarding succeeded before re-POSTing with a fresh key
    REQ
  • 401 triggers token refresh Expired token results in re-authentication, not a silent failure or infinite retry
    REQ

Terminal Ordering — Gateway_Payroc — separate workflow
0 / 5 ▼
Separate workflow. Terminal orders are submitted after the processing account reaches approved status (confirmed via processingAccount.status.changed webhook). The Gateway_Payroc solution template provisions a software gateway — no physical hardware ships.
POST https://api.uat.payroc.com/v1/processing-accounts/{processingAccountId}/terminal-orders
{ "trainingProvider": "partner", "orderItems": [ { "type": "solution", "solutionTemplateId": "Gateway_Payroc", "solutionQuantity": 1, "solutionSetup": { "timezone": "America/Chicago", "industryTemplateId": "Retail", "batchClosure": { "batchCloseType": "automatic", "batchCloseTime": "23:00" }, "tokenization": true, "tips": { "enabled": false } } } ] // shipping omitted — Gateway_Payroc is software; no hardware ships }
